02 · เข้าแอปและสลับหน้า

เริ่มจาก main() แล้วผ่าน AuthGate

lib/main.dart เป็นจุดเริ่มโปรแกรมและประกอบหน้าแอป หลัง initialize Firebase แล้ว AuthGate ฟังสถานะ login: ยังไม่ login แสดง AuthPage; มีบัญชีแล้วสร้าง MainPage พร้อม repository ที่รู้ UID

Future<void> main() async {
  // ผูก Flutter กับ native engine เพื่อให้เรียก plugin ได้ก่อน runApp
  WidgetsFlutterBinding.ensureInitialized();
  // รอ Firebase พร้อม และเลือก config ให้ตรงกับ iOS/Android/Web
  await Firebase.initializeApp(
    options: DefaultFirebaseOptions.currentPlatform,
  );
  // เริ่มวาด widget หลักหลัง Firebase พร้อมแล้ว
  runApp(const SteamFavoriteApp());
}

// ตัวอย่างย่อจาก AuthGate: ฟังสถานะ login ที่เปลี่ยนแบบ stream
// ไม่มีผู้ใช้ = ส่งไปหน้าล็อกอิน; มีผู้ใช้ = เข้าแอปพร้อม repository
if (snapshot.data == null) return AuthPage(auth: _auth);
return MainPage(
  // repository จะใช้ UID ของผู้ใช้จัดขอบเขตข้อมูล
  repository: FirestoreGameRepository(auth: _auth),
  // ส่ง User ต่อให้หน้า About/เมนูโปรไฟล์ใช้แสดงข้อมูล
  user: snapshot.data,
);
  • ensureInitialized() เตรียม Flutter engine ก่อนเรียก plugin ใน main
  • await รอ Firebase พร้อมก่อนสร้าง widget ที่ต้องใช้ Firebase
  • IndexedStack กับ CupertinoTabBar สลับแท็บ แต่รักษา state ของหน้าเดิม

03 · เกมโปรดและฟอร์ม

แตะรายการ → ส่ง Model → เปิดรายละเอียด

ใน lib/main.dart เมธอด _openDetail ส่ง object SteamGame ผ่าน constructor ของหน้าใหม่ด้วย Navigator/MaterialPageRoute ข้อมูลที่มีอยู่จึงแสดงได้ทันที

Future<void> _openDetail(SteamGame game) async {
  // เปิดหน้าถัดไปและรอจนผู้ใช้ย้อนกลับ
  await Navigator.push(
    context,
    // กำหนดเส้นทางแบบ Material ให้ Flutter สร้าง GameDetailPage
    MaterialPageRoute(
      builder: (_) => GameDetailPage(
        // ส่ง object เกมทั้งก้อนผ่าน constructor ไม่ต้องค้น DB ซ้ำ
        game: game,
        // ส่ง repository เพื่อให้หน้ารายละเอียดแก้/ลบข้อมูลได้
        repository: widget.repository,
      ),
    ),
  );
}

lib/pages/game_editor_page.dart มี TextFormField และ validator; Dropdown/Slider หรือ widget เลือกค่าอัปเดต state ก่อนประกอบเป็น SteamGame แล้วเรียก repository.saveGame ส่วนการลบมี dialog ยืนยันก่อนเรียก deleteGame

ถ้าการเขียนสำเร็จ service คืนเกมที่ server ตอบกลับมา แล้ว repository บันทึก cache ต่อ หาก API ล้มเหลว UI จะแสดง error และไม่ทำเหมือนว่าบันทึกสำเร็จ

04 · ฟีเจอร์รีวิวรายเกม · CRUD API

รีวิวอยู่ในหน้ารายละเอียด ไม่ใช่หน้าแยก

lib/widgets/game_review_section.dart วาดการ์ด “รีวิวของฉัน” ต่อท้ายข้อมูลเกม มีช่องข้อความตรวจห้ามว่างและ Slider ให้คะแนน 0–5 ดาว เมื่อโหลดหน้าจะ GET รายการจาก server แล้วเลือกรีวิวที่มี appId ตรงกัน ถ้าเป็นข้อมูลรุ่นเก่าที่ไม่มี appId จะลองเทียบชื่อเกม

กล่องข้อมูลของนักศึกษาhttps://thipwimon.comsciproject.net/mydiary/api.php/67011212055ส่งฟิลด์ title, content, mood (คะแนน), date และ appId · ไม่ต้องใส่ cleartext traffic เพราะเป็น HTTPS
GETgetDiaries()อ่านรายการทั้งหมดจากกล่อง แล้วกรองให้ตรงเกมนี้
POSTcreateDiary(review)สร้างรีวิวใหม่เมื่อเกมนี้ยังไม่มีรีวิว
PUTupdateDiary(review)แก้รายการเดิมด้วย id ที่ API คืนให้
DELETEdeleteDiary(id)ลบหลังผู้ใช้ยืนยันใน dialog

จุดโค้ดที่ควรไล่อธิบาย

// lib/services/diary_api_service.dart
// รหัสนี้ต่อท้าย URL เพื่อแยกกล่องข้อมูลของนักศึกษา
static const studentId = '67011212055';
// endpoint หลักที่ใช้ร่วมกันสำหรับ CRUD รีวิว
static const defaultEndpoint =
  'https://thipwimon.comsciproject.net/mydiary/api.php/$studentId';

// POST สร้างรีวิวใหม่ โดยแปลง model เป็น JSON ส่งใน request body
Future<void> createDiary(GameReview review) async {
  await _send('POST', _baseUri, body: review.toJson());
}

// PUT แก้รีวิวเดิม โดยใส่ id ต่อท้าย URL เพื่อชี้รายการเป้าหมาย
Future<void> updateDiary(GameReview review) async {
  await _send('PUT', Uri.parse('$endpoint/${review.id}'),
    body: review.toJson());
}

// DELETE ลบรายการตาม id; _send ตรวจ status และโยน error หากไม่สำเร็จ
Future<void> deleteDiary(String id) async {
  await _send('DELETE', Uri.parse('$endpoint/$id'));
}

เมธอดทั้งสี่ใช้ http.Request, JSON header, timeout 15 วินาที และตรวจ HTTP status 2xx หากล้มเหลวจะแปลงเป็น DiaryApiException เพื่อให้ UI แจ้งผู้ใช้ได้ ส่วน lib/models/game_review.dart แปลง JSON ↔ object และอ่านได้ทั้ง id กับ _id จาก response

ยืนยันการทำงานกับ endpoint จริง: POST 201 · PUT 200 · DELETE 200 รายการที่ใช้ตรวจเป็นรายการชั่วคราวและลบออกหลังทดสอบแล้ว ไม่ได้แก้ไขข้อมูลเดิม

lib/services/api_service.dart โหลดเกมแนะนำและคอมเมนต์ ส่วน recommended_games_page.dart และ community_page.dart ใช้ FutureBuilder แยกสถานะการโหลด

06 · Model และการแปลงข้อมูล

ข้อมูลหนึ่งชุด แต่อาจต้องแปลงหลายรูปแบบ

SteamGame เป็น model เกมโปรดหลัก ใช้ field เช่น title, description, genre, imageUrl, rating, isFavorite และ userId ส่วน toFirestore/fromFirestore, toJson/fromJson, toMap/fromMap จัดการโครงสร้างปลายทางแต่ละแบบ

// SQLite ไม่มีชนิด boolean โดยตรงในรูปแบบนี้
// จึงแปลง true/false เป็นเลข 1/0 ตอนเขียนลงตาราง
'isFavorite': isFavorite ? 1 : 0,

// JSON / Firestore เก็บ boolean ได้โดยตรง
// ไม่ต้องแปลง; model รับค่า true/false ได้เลย
'isFavorite': isFavorite,

RecommendedGame คือข้อมูลเกมที่เพิ่งมาจาก API ก่อนบันทึกเป็นรายการโปรด · BacklogGame คือเกมที่อยากเล่น · GameComment คือคอมเมนต์ในชุมชน · GameReview คือรีวิวส่วนตัวที่ API เก็บ

07 · Authentication และข้อมูล Cloud

UID กับ ID token ใช้คนละหน้าที่

auth_page.dart จัดการหน้าล็อกอิน/สมัครบัญชี; firestore_game_repository.dart อ่าน UID จาก FirebaseAuth เพื่อแยกข้อมูล แล้วขอ ID token เพื่อยืนยันคำขอกับ Favorites API

String get _userId {
  // อ่าน UID จาก Firebase Auth ของ session ปัจจุบัน
  final id = _auth.currentUser?.uid;
  // ปฏิเสธการเรียกข้อมูลถ้ายังไม่มีผู้ใช้ล็อกอิน
  if (id == null) throw StateError('ผู้ใช้ยังไม่ได้เข้าสู่ระบบ');
  // ส่ง UID กลับไปใช้ระบุเจ้าของรายการ
  return id;
}

// ขอ Firebase ID token เพื่อแนบ Authorization: Bearer ให้ REST API
Future<String> get _idToken async =>
  await _auth.currentUser?.getIdToken() ??
  // ถ้า session หมดอายุ/ไม่มีผู้ใช้ ให้ส่ง error แทนเรียก API เปล่า ๆ
  (throw StateError('กรุณาเข้าสู่ระบบใหม่'));

ส่วน favorites_api_service.dart แนบ Authorization: Bearer <ID token> ทุก request และส่ง GET/POST/PUT/DELETE ไป backend ของรายการโปรด การซ่อนข้อมูลด้วย filter ในแอปอย่างเดียวไม่ใช่ security; server และ Firestore Rules ต้องตรวจสิทธิ์ด้วย

08 · SQLite และ platform

มือถือกับเว็บเลือก storage adapter คนละตัว

game_database.dart กำหนด interface และ conditional import · game_database_sqflite.dart ใช้ sqflite บน iOS/Android · game_database_web.dart ใช้ SharedPreferences บนเว็บ · game_database_stub.dart แจ้ง unsupported บน platform อื่น

backlog_page.dart ใช้ local database นี้สำหรับ CRUD ของ Backlog; database version migration สร้างตาราง backlog โดยไม่แทนตารางเกมเดิม

พูดตรงข้อเท็จจริง: รีวิวเก็บบน REST server · เกมโปรดเป็น Cloud/Firestore พร้อม SQLite cache · Backlog เป็น local storage · เว็บใช้ adapter ของ browser ไม่ใช่ sqflite จริง

09 · กราฟและสถิติ

สถิติคำนวณจากเกมโปรดที่โหลดได้

GameStatisticsPage ใน main.dart นับเกมตาม genre แล้ววาด donut ด้วย CustomPainter ส่วน ChoiceChip เลือก “ทั้งหมด” หรือหมวดเดียวได้; เมื่อเลือกหมวด วงแหวนแบ่งเกมโปรดกับเกมอื่นในหมวด และรายการด้านล่างกรองเหลือหมวดนั้น

การวาดกราฟแปลงจำนวนแต่ละกลุ่มเป็นสัดส่วนของผลรวม แล้วใช้ canvas.drawArc วาด segment ต่อกันรอบวง

10 · สารบัญ source พร้อมโค้ดเต็ม

เปิดไฟล์จริง อ่าน หรือดาวน์โหลด

เปิดแถบของไฟล์เพื่อดึง source code ปัจจุบันจากโปรเจกต์มาแสดงตรงนี้ กด “ดาวน์โหลดไฟล์” เพื่อเก็บต้นฉบับ หรือ “คัดลอกโค้ด” เพื่อวางใน editor แล้วค้นตาม symbol ที่อธิบายไว้ข้างไฟล์

จำไว้ตอนตอบอาจารย์

อธิบายเป็นลำดับเดียวกันทุกฟีเจอร์

ผู้ใช้ทำอะไร → widget ไหนรับ event → model หน้าตาอย่างไร → service/repository ส่งไปไหน → data กลับมาแล้ว UI เปลี่ยนอย่างไร → ถ้าล้มเหลวแสดงอะไร

คู่มือนี้มี source path ให้กดเปิดเทียบทุกจุด โค้ดเต็มในส่วนท้ายโหลดจากไฟล์จริง ไม่ใช่โค้ดตัวอย่างที่พิมพ์ซ้ำ
