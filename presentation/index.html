04 · DATA MODEL

Model คือรูปแบบข้อมูลเกมหนึ่งรายการ

SteamGame รวมข้อมูลที่ทุกหน้าต้องใช้ไว้ใน class เดียว ทำให้ฟอร์ม รายละเอียด API, Firestore และ SQLite พูดภาษาเดียวกัน

lib/models/steam_game.dartฟิลด์ + การแปลงข้อมูล
class SteamGame {
  final String? id;
  final String userId;
  final String appId;
  final String title;
  final String description;
  final String date;
  final String mood;
  final String genre;
  final String imageUrl;
  final double rating;
  final bool isFavorite;

  const SteamGame({
    this.id,
    this.userId = '',
    required this.appId,
    required this.title,
    required this.description,
    required this.date,
    this.mood = 'อื่น ๆ',
    String? genre,
    required this.imageUrl,
    required this.rating,
    this.isFavorite = true,
  }) : genre = genre ?? mood;

  Map<String, Object?> toMap({String? userId}) => {
    'id': id, 'userId': userId ?? this.userId,
    'appId': appId, 'title': title,
    'description': description, 'date': date,
    'genre': genre, 'imageUrl': imageUrl,
    'rating': rating, 'isFavorite': isFavorite ? 1 : 0,
  };
}
id

เป็น nullable เพราะรายการใหม่ยังไม่มี document ID ก่อนบันทึก

userId

ใช้แยกเจ้าของข้อมูล ไม่ควรเชื่อค่าจากหน้าจอ; repository กำหนดจากบัญชีที่ล็อกอิน

toMap()

แปลง object เป็น map เพื่อส่ง SQLite; boolean กลายเป็น 0/1 ตามชนิดข้อมูล SQLite

โค้ดเต็ม: lib/models/steam_game.dart · บรรทัด 3–120 (หน้าเว็บยกเฉพาะส่วนสำคัญ)

ทำไมต้องมี Model?

ลดการส่ง map ดิบไปทั่วแอป, กำหนดชนิดข้อมูลชัดเจน, รวมการ serialize/deserialize ไว้จุดเดียว และทำให้ทดสอบได้ง่าย

ข้อมูลหนึ่งเกมมีอะไรบ้าง?

ชื่อ, รายละเอียด, วัน, หมวด, URL/ข้อมูลภาพ, คะแนน, สถานะ favorite, Steam App ID และเจ้าของบัญชี

Future<void> _save() async {
  if (_saving || !_formKey.currentState!.validate()) return;
  setState(() {
    _saving = true;
    _error = null;
  });
  try {
    final saved = await widget.repository.saveGame(
      SteamGame(
        id: widget.game?.id,
        appId: _appId.text.trim(),
        title: _title.text.trim(),
        description: _description.text.trim(),
        date: _date,
        mood: _genre,

        imageUrl: _image.text.trim(),
        rating: _rating,
        isFavorite: _isFavorite,
      ),
    );

  } catch (_) {

}

ทำไมมี empty state?

function ownsExistingGame() {
  return request.auth != null
    && resource.data.userId == request.auth.uid;
}

function ownsIncomingGame() {
  return request.auth != null
    && request.resource.data.userId == request.auth.uid;
}

allow create: if ownsIncomingGame() && validGame();
allow read, delete: if ownsExistingGame();
allow update: if ownsExistingGame()
              && ownsIncomingGame()
              && validGame();

คำตอบที่ควรจำ

“ตอนอ่านใช้ UID ที่ล็อกอินกรอง query และ Rules เช็กซ้ำจาก request.auth.uid; ตอนเขียน Rules ตรวจทั้งเจ้าของข้อมูลเดิมและเจ้าของข้อมูลใหม่ เพื่อกันการย้ายเอกสารไปเป็นของคนอื่น”

11 · ORAL EXAM PRACTICE

คำถามที่น่าจะโดนถาม

กดเปิดคำตอบเพื่อซ้อมพูดด้วยภาษาของตัวเอง

ทำไมต้องมี Model class?

เพื่อกำหนดชนิดและ field ของเกมให้ชัด แล้วรวมการแปลง Map/JSON/Firestore ไว้ที่ SteamGame ทำให้ทุกหน้าใช้ข้อมูลรูปแบบเดียวกัน

FutureBuilder มีหน้าที่อะไร?

รับ Future แล้ว rebuild ตามสถานะ asynchronous ได้แก่กำลังโหลด, ได้ผล, error; ในแอปยังแยก empty list จาก error และมีปุ่ม retry

REST CRUD ใช้ method อะไร?

GET อ่าน, POST สร้าง, PUT แก้ไข และ DELETE ลบ; favorites API แนบ Firebase ID token ใน Authorization header

ทำไมต้องมีทั้ง Firestore กับ SQLite?

Firestore เป็นข้อมูล Cloud สำหรับแยกผู้ใช้และซิงก์ข้ามอุปกรณ์; SQLite เป็นสำเนาในเครื่องเพื่อเปิดดูรายการที่เคยโหลดได้เมื่อกลับเข้าหน้า

ถ้าไม่มีอินเทอร์เน็ต เพิ่มเกมได้ไหม?

เวอร์ชันนี้ยังบันทึกเพิ่ม/แก้/ลบแบบออฟไลน์ไม่ได้ เพราะ repository เรียก API ก่อนแล้วค่อยอัปเดต SQLite; แต่สามารถอ่านข้อมูลที่ cache ไว้ได้

Rules ป้องกันผู้ใช้เห็นเกมคนอื่นอย่างไร?

ทุกเอกสารมี userId; Rule เช็กว่าผู้ใช้ลงชื่อเข้าใช้และ UID ตรงกับเจ้าของเอกสาร ทั้งตอนอ่าน/ลบ และเช็ก owner เดิม/ใหม่ตอนแก้ไข

จะรู้ได้อย่างไรว่าการเพิ่มสำเร็จ?

API ตอบกลับสำเร็จแล้ว Repository บันทึกสำเนาในเครื่อง; จากนั้น Firestore snapshots ส่งรายการใหม่ ทำให้ StreamBuilder วาดรายการล่าสุด

ป้องกันรูปใหญ่เกินไปอย่างไร?

ก่อนเก็บ รูปถูกหมุนตาม orientation, ย่อหลายขนาดและลด JPEG quality จนไม่เกิน 250 KB; ฝั่ง API ยังจำกัดความยาว image data อีกชั้น

กราฟสถิติคำนวณจากอะไร?

วนรายการเกมเพื่อสะสมจำนวนต่อ genre, นับ isFavorite และหารจำนวนเกมโปรดด้วยจำนวนเกมทั้งหมดเพื่อได้ ratio; แถบกราฟ normalize เทียบกับหมวดที่มีจำนวนมากที่สุด

ทำไมเว็บกับมือถือเก็บ local ไม่เหมือนกัน?

mobile ใช้ sqflite; เว็บใช้ SharedPreferences adapter เพราะ plugin/ฐานข้อมูลบน browser มี runtime ต่างกัน แต่ทั้งคู่ทำตาม interface GameDatabase เดียวกัน
