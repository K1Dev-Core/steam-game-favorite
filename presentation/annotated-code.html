02 · MODEL & SERIALIZATION

Model กลางและการแปลงข้อมูล

อ้างอิง lib/models/steam_game.dart Model เดียวกันใช้กับ SQLite, REST JSON และ Firestore แต่ต้องแปลง boolean ต่างกันตามรูปแบบปลายทาง

class SteamGame {
  final String? id;       // null = ยังไม่มี id จากการบันทึก
  final String userId;     // เจ้าของข้อมูล; มาจากบัญชีที่ยืนยันแล้ว
  final String title;
  final String genre;
  final double rating;
  final bool isFavorite;

  // SQLite ต้องเก็บ bool เป็น integer 0/1
  Map<String, Object?> toMap({String? userId}) => {
    'id': id,
    'userId': userId ?? this.userId,
    'title': title,
    'genre': genre,
    'rating': rating,
    'isFavorite': isFavorite ? 1 : 0,
  };

  // REST JSON/Firestore ใช้ boolean จริง ไม่ใช่เลข 0/1
  Map<String, Object?> toJson() => {
    'id': id,
    'userId': userId,
    'title': title,
    'genre': genre,
    'rating': rating,
    'isFavorite': isFavorite,
  };
}
จำง่าย: toMap/fromMap ใช้กับแถว local; toJson/fromJson ใช้กับ HTTP; toFirestore/fromFirestore แปลง Firestore document โดยอ่าน document id จาก Firestore metadata

05 · REPOSITORY

เชื่อม Cloud กับ cache

อ้างอิง lib/services/firestore_game_repository.dart repository ทำให้ UI เรียก watch/save/delete โดยไม่รู้ขั้นตอน HTTP และ local DB ทั้งหมด

Stream<List<SteamGame>> watchGames() async* {
  final userId = _userId; // อ่าน UID จาก Firebase Auth
  yield await _database.readGames(userId); // แสดง cache ก่อน

  try {
    final token = await _idToken; // credential ของ session ปัจจุบัน
    final latest = await _api.getGames(token); // Cloud/API เป็นข้อมูลหลัก
    await _database.replaceGames(userId, latest); // refresh local copy
    yield await _database.readGames(userId); // ส่งข้อมูลใหม่ให้ UI
  } catch (_) {
    // ถ้า refresh ไม่สำเร็จ อย่างน้อยผู้ใช้ยังเห็น cache เดิม
  }

  // Firestore stream ทำให้รายการอัปเดต real-time
  await for (final snapshot in _games
      .where('userId', isEqualTo: userId).snapshots()) {
    final games = snapshot.docs.map(SteamGame.fromFirestore).toList();
    await _database.replaceGames(userId, games);
    yield await _database.readGames(userId);
  }
}
ข้อจำกัดต้องพูดตรง: save/delete เรียก API ก่อน แล้วค่อยแก้ SQLite; ออฟไลน์จึงไม่มี write queue สำหรับซิงก์ภายหลัง

10 · FIRESTORE RULES

ตรวจทั้งเจ้าของเดิมและข้อมูลใหม่

กติกาจริงอยู่ใน firestore.rules; การกรอง query ใน UI ไม่ทดแทน Rules

function ownsExistingGame() {
  // resource = document ปัจจุบันในฐานข้อมูล
  return request.auth != null
      && resource.data.userId == request.auth.uid;
}

function ownsIncomingGame() {
  // request.resource = ค่าที่กำลังจะเขียน
  return request.auth != null
      && request.resource.data.userId == request.auth.uid;
}

allow create: if ownsIncomingGame() && validGame();
allow read, delete: if ownsExistingGame();
allow update: if ownsExistingGame()
              && ownsIncomingGame()
              // ห้ามเปลี่ยน owner ระหว่าง update
              && request.resource.data.userId == resource.data.userId
              && validGame();

12 · Q&A PRACTICE

คำถาม–คำตอบซ้อมพรีเซนต์

พยายามตอบด้วยภาษาตัวเอง แล้วชี้ไฟล์หรือสาธิตหลักฐานจริงประกอบ

แอปนี้แก้ปัญหาอะไร?

ช่วยรวบรวมเกมที่สนใจไว้ในบัญชีเดียว เพิ่มรายละเอียด หมวด คะแนน และรูปได้ พร้อมดูเกมแนะนำและสรุปสถิติ

ทำไมเลือก Flutter?

เขียน UI ด้วย Dart ชุดเดียวและนำไป build Android, iOS และ Web ได้ โดยใช้ widget และ plugin ตาม platform

StatefulWidget กับ setState ใช้ตรงไหน?

ใช้กับค่าที่เปลี่ยนระหว่างใช้งาน เช่น tab, ตัวกรอง, ฟอร์ม และสถานะ loading; เรียก setState เพื่อให้ framework สร้าง UI ใหม่

Model SteamGame มี field อะไรและทำไมต้องมี?

มี id, userId, appId, title, description, date, mood/genre, imageUrl, rating และ isFavorite เพื่อกำหนดรูปข้อมูลเดียวให้หลายชั้นใช้ตรงกัน

ทำไม toMap กับ toJson แยกกัน?

SQLite แทน bool ด้วย integer 0/1 ส่วน JSON/Firestore รองรับ bool จริง; แยก serializer ทำให้ชนิดข้อมูลถูกตาม backend

เพิ่มกับแก้ไขแยกกันอย่างไร?

ฟอร์มใหม่ไม่มี id จึง repository สร้าง id แล้ว POST; ตอนแก้ส่ง id เดิมและใช้ PUT อัปเดต record เดิม

validator ทำงานอย่างไร?

Form เรียก validator ของแต่ละ TextFormField; คืนข้อความเมื่อผิดหรือ null เมื่อผ่าน; _save ไม่เรียก backend หาก form ไม่ผ่าน

ทำไมตรวจ mounted หลัง await?

ระหว่างรอ network ผู้ใช้อาจปิดหน้าไปแล้ว; mounted ป้องกันใช้ context/setState หลัง State ถูก dispose

Navigator.push และ MaterialPageRoute ทำอะไร?

push เปิด route ใหม่บน navigation stack; MaterialPageRoute สร้างหน้ารายละเอียดและส่ง model ผ่าน constructor

FutureBuilder มีสถานะอะไร?

ConnectionState ใช้แยกกำลังรอ; hasError แยก error; data ว่างเป็น empty state; มีข้อมูลจึงวาด list

ทำไมเก็บ Future ใน State?

กัน request ซ้ำจาก rebuild; refresh/retry เท่านั้นที่สร้าง Future ใหม่

SQLite เป็นฐานข้อมูลหลักหรือไม่?

ไม่ใช่ใน flow นี้ เป็นสำเนา local; remote API/Firestore ใช้การเขียนหลักและข้อมูล stream ล่าสุดแทน cache

ทำงาน offline ได้แค่ไหน?

อ่านข้อมูลที่เคย cache ได้ในบางช่วง แต่เพิ่ม/แก้/ลบไม่ถูก queue ส่งภายหลัง; ต้องออนไลน์เพื่อเขียน Cloud

ทำไม mobile กับ web มี adapter ต่างกัน?

sqflite เป็นแนว native; browser มี runtime/storage ต่างกัน จึงใช้ conditional import เลือก adapter โดยคง interface เดียวกัน

REST API มี method อะไร?

GET อ่าน, POST สร้าง, PUT แก้ไข, DELETE ลบ; status 2xx ถือว่าสำเร็จ ส่วน error ถูกแปลงเป็น ApiException

Firebase ID token ใช้ทำอะไร?

พิสูจน์ session ของผู้ใช้ตอนเรียก private API; server ส่งต่อ token ให้ Firestore ตรวจตัวตนและ Rules

API decode JWT แล้วพอปลอดภัยหรือยัง?

ไม่พอ การอ่าน claim อย่างเดียวไม่ verify ลายเซ็น; ในโค้ดส่ง token ต่อให้ Firestore ซึ่งต้องตรวจ token จริงและบังคับ Rules; ควรยืนยันด้วยการทดสอบบัญชีจริงและ deployment ที่ใช้

Firestore Rules ป้องกันเห็นข้อมูลคนอื่นอย่างไร?

ตรวจ request.auth ไม่เป็น null และ userId เท่ากับ UID; read/delete ตรวจ document เดิม ส่วน create/update ตรวจข้อมูลใหม่ด้วย

ทำไม update ตรวจ owner สองครั้ง?

ต้องเป็นเจ้าของ document เดิมและข้อมูลที่เขียนใหม่ยังระบุ owner เดิม ป้องกันย้าย document ไปบัญชีอื่น

กรองผู้ใช้ใน UI อย่างเดียวพอไหม?

ไม่พอ เพราะ client ถูกแก้หรือเรียก endpoint ตรงได้; ต้องจำกัดที่ API/Firestore Rules ด้วย

API key ใน Firebase config เป็นรหัสผ่านไหม?

โดยทั่วไปเป็น identifier/config สำหรับ client ไม่ใช่ private key; แต่ Rules ต้องเข้ม และห้ามเผยแพร่ service-account private key, user token หรือ password

รูปจาก API เสียจะเกิดอะไร?

GameArtwork แสดง placeholder ระหว่างโหลดและ error fallback เมื่อโหลดไม่สำเร็จ แทนการปล่อยภาพเสียหรือหน้าพัง

รูปจากกล้องลดขนาดอย่างไร?

แก้ orientation ตาม EXIF, resize ลดขอบภาพเป็นขั้น และลด JPEG quality จนได้ไม่เกินประมาณ 250 KB

สถิติคำนวณจากไหน?

คำนวณจาก list เกมที่ได้มา นับจำนวนแต่ละ genre และ favorite แล้วแสดงตัวเลข/กราฟ; ไม่ได้เก็บยอดซ้ำแยกอีกฐาน

ทำไมกราฟใช้สี index % colors.length?

เลือกสีตามลำดับหมวด; modulo ทำให้สีวนกลับเมื่อจำนวนหมวดมากกว่าจำนวนสีที่เตรียมไว้และไม่เกิด index เกินขอบเขต

empty state กับ error state ต่างกันอย่างไร?

empty คือ request สำเร็จแต่ไม่มีข้อมูล; error คือโหลดไม่สำเร็จ จึงควรแสดงข้อความและ action ที่ต่างกัน

ถ้าบันทึก API สำเร็จแต่ cache ล้มเหลว?

Cloud อาจมีข้อมูลแล้วแต่ local mirror บันทึกไม่สำเร็จ; รอบโหลดถัดไปสามารถดึง cloud มาแทน cache; ควรตรวจ log/error และอย่าอ้างว่า transaction กระจายข้ามระบบ

มี test อะไรบ้าง?

มี API/UI tests, CRUD tests ด้วย fake repository และ widget tests; นอกเหนือจากนั้นต้องทดลอง deployment, Auth, Rules, network และเครื่องจริงแยก

พิสูจน์ว่าข้อมูลแยก user ได้อย่างไร?

ล็อกอินบัญชี A เพิ่มเกม, logout แล้วบัญชี B ต้องไม่เห็น; ตรวจ userId ใน Firestore และลอง Rules/endpoint ด้วย token ของแต่ละบัญชี

อะไรคือข้อจำกัดที่ยอมรับได้ของงาน?

การเขียนต้องออนไลน์, local cache ไม่ใช่ offline sync, รูป data URI มีข้อจำกัดขนาด, และ behavior จริงขึ้นกับ API/Rules ที่ deploy; บอกตรงพร้อมแนวพัฒนาต่อ เช่น queued writes และ token verification ฝั่ง middleware

ถ้ามีเวลาพัฒนาต่อจะทำอะไร?

เพิ่ม offline write queue พร้อม conflict policy, retry/backoff, integration tests กับ Firebase Emulator, pagination/search ฝั่ง server และอัปโหลดรูปไป object storage แทนเก็บ data URI ใน document
